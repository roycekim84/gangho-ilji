# 《강호일지》 100% 근접 통합 구현 로드맵

평가 기준일: 2026-08-28  
현재 기준: `v0.1.1-alpha`, 시안 대비 출시 전 완성도 약 74%

이 문서는 기능·시각·연출·품질을 함께 끌어올려 콘셉트 시안과 실제 플레이 화면의 차이를 최소화하기 위한 통합 실행 계획이다. 새로운 온라인 서비스 기능은 범위에 포함하지 않는다.

## 1. 최종 목표

“새 저장 슬롯에서 시작해 7개 지역, 7개 보스, 최종 엔딩까지 막힘없이 진행되고, 10개 핵심 화면이 동일한 무협 서책의 장면처럼 보이며, 320~520px에서 안정적으로 동작하는 로컬 완성판 알파”를 100%로 정의한다.

100%는 기능을 무한히 늘린다는 뜻이 아니라 다음 네 축의 완료를 의미한다.

| 축 | 현재 | 100% 목표 |
|---|---:|---:|
| 플레이 기능 | 88% | 100% |
| 화면 구조·정보 위계 | 82% | 98% |
| 아트·연출 | 62% | 95% |
| 품질·접근성·배포 | 80% | 98% |

## 2. 단계별 로드맵

### Phase 0 — 기준선 고정 (완료)

- 핵심 게임 루프와 저장 구조 동결
- 10개 화면 목록과 시안 대응 관계 확정
- 공통 색상 토큰, `ArtworkFrame`, 상태 패널, 하단 네비게이션 정리
- 7지역·7보스·무공·경맥·기연·오프라인 보상 플레이 가능

완료 기준: 새 저장에서 메인 루프가 실행되고 회귀 테스트가 통과한다.

### Phase 1 — P0 기능 완주 안정화 (목표: 80%)

1. 새 저장 → 낙양 외곽 → 천마봉 → 엔딩 스모크 테스트 자동화
2. 보스 7명 각각의 도전·승리·해금·보상 검증
3. 장비 드랍·장착·분해·잠금·비교의 상태 조합 검증
4. 무공 5슬롯·숙련도·경맥 개방이 전투 결과에 반영되는지 검증
5. 오프라인 보상 0분/8시간/초과 시간 경계값 검증
6. 저장 직후 새로고침·재접속·브라우저 종료 후 복원 검증

완료 기준: 치명적 진행 막힘 0건, 핵심 루프 자동 스모크 테스트 1회 이상 통과.

### Phase 2 — 시안 수준 화면 위계 완성 (목표: 86%)

1. 시작 화면: 저장 슬롯 상태, 버전, 새 강호/이어하기 우선순위
2. 강호 메인: 상태→지역→전투→로그→자동전투 고정 및 첫 viewport 보장
3. 지역 선택·상세: 7개 카드의 잠금·진행·권장 경지·드랍·보스 비교
4. 보스 전투: 보스 초상·기혈·교전 상태·승리 보상 패널
5. 무인·장비: 능력치 투자, 8슬롯 등급 프레임, 장비 비교 위계
6. 무도·경맥: 5슬롯, 숙련도, 중앙 노드와 분기 경로 강조
7. 기연·강호록: 사건 삽화, 선택지, 결과, 기록 아이콘의 정보 순서

완료 기준: 10개 화면을 시안과 나란히 비교했을 때 동일한 정보 구조로 인식된다.

### Phase 3 — 전용 아트와 연출 확장 (목표: 92%)

- 7지역 배경·7보스·주인공·일반 적 아트의 톤/명암 통일
- 8장비 슬롯과 4등급 아이콘 세트 확장
- 검·도·권·암기·심법 비급 표지 계열 아트 추가
- 강호록 종이 질감·문양·기록 도장 세트 추가
- 장비 획득, 장착, 분해, 경맥 개방, 무공 세팅에 150~300ms 피드백
- 보스 승리→보상→다음 지역 해금 전환 연출
- 기연 선택→결과 문구→보상 반영 순서 명확화

완료 기준: 공용 placeholder가 핵심 카드에 남지 않고, 주요 상태 변화가 색상·아이콘·텍스트 중 2가지 이상으로 피드백된다.

### Phase 4 — 텍스트·밸런스·접근성 마감 (목표: 96%)

- 전투 로그 문장 패턴과 피해/치명타/회피/획득 용어집 확정
- 지역·보스·기연 설명을 짧은 무협 문장으로 편집
- 숫자 표기, 단위, 퍼센트, 경지 표기 규칙 통일
- 44px 이상 터치 영역과 키보드 포커스 순서 확인
- 주요 버튼·게이지·로그·모달에 Semantics 라벨/상태 추가
- 색상 대비와 색맹 환경에서 상태 구분 검수
- 레벨 속도·드랍률·보스 체력·오프라인 보상 최종 조정

완료 기준: 스크린리더가 주요 화면을 논리적 순서로 읽고, 신규 플레이어가 별도 설명 없이 첫 지역을 진행한다.

### Phase 5 — 출시 후보 검증 (목표: 98~100%)

- 320×700, 390×844, 520×900 스냅샷 검수
- 시작·이어하기·새로고침·오프라인 보상·엔딩 전체 회귀
- Chrome/모바일 브라우저에서 asset 누락·콘솔 오류 확인
- `flutter analyze`, `flutter test`, `flutter build web --release` PR 게이트화
- GitHub Pages 캐시 갱신 및 실제 공개 링크 스모크 테스트
- 릴리스 노트·변경 내역·알려진 제한사항 작성
- `v0.2.0-alpha` 태그 및 후보 릴리스 생성

완료 기준: 치명적 오류 0건, P0 미해결 0건, 콘솔 오류 0건, 세 뷰포트 overflow 0건.

## 3. 작업 우선순위 규칙

1. 진행을 막는 버그와 저장 손상 가능성
2. 보스 승리·장비 획득·기연 결과처럼 성장 체감을 만드는 피드백
3. 10개 화면의 정보 위계와 전용 아트
4. 텍스트 편집과 밸런스
5. 사운드와 장식적 모션

각 작업은 하나의 화면 또는 하나의 공통 컴포넌트만 다루고, `feat:`, `fix:`, `test:`, `docs:` 중 하나의 커밋으로 남긴다. 작업 완료 시 `docs/dev_log.md`와 이 문서의 진행률을 함께 갱신한다.

## 4. 진행률 산정 방식

전체 점수는 기능 40%, 시각/연출 30%, 품질/접근성 20%, 문서/배포 10%로 계산한다.

- 기능: 핵심 루프·콘텐츠·저장·엔딩 통과율
- 시각/연출: 시안 비교 리뷰에서 구조·아트·상태 피드백 점수
- 품질: 테스트·뷰포트·접근성·콘솔 오류 결과
- 문서/배포: 로드맵·로그·릴리스·공개 링크 최신성

현재 추정치는 74%이며, Phase 1 완료 시 약 80%, Phase 2 완료 시 약 86%, Phase 3 완료 시 약 92%, Phase 4~5 완료 시 98~100%를 목표로 한다.

## 5. 출시 보류 조건

- 저장 데이터가 새로고침 또는 재접속 후 사라짐
- 특정 보스 또는 지역에서 진행이 막힘
- 핵심 화면에서 텍스트가 잘리거나 가로 overflow 발생
- 보상·장비·경맥 상태가 화면 표시와 실제 계산에서 불일치
- Pages 공개 빌드 실패 또는 콘솔 치명 오류

이 조건 중 하나라도 남아 있으면 시각 장식보다 안정화 작업을 우선한다.
