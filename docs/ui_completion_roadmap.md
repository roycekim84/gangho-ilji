# 《강호일지》 시안 완성도 달성 로드맵

## 1. 목표와 현재 위치

첨부된 10면 콘셉트 시안을 최종 시각 기준으로 삼는다. 현재 버전은 7개 지역 자동 전투, 성장·장비·무공·경맥·기연·오프라인 보상·엔딩이 플레이 가능한 `v0.1.1-alpha`다.

다음 목표는 기능 수를 늘리는 것이 아니라, 시안처럼 각 화면이 하나의 무협 서책에서 나온 장면처럼 보이고 정보 밀도·위계·상태 피드백이 완성된 제품 수준에 도달하는 것이다.

## 2. 시안 대비 핵심 격차

| 영역 | 현재 상태 | 목표 상태 |
|---|---|---|
| 아트 | 공용/대표 일러스트 중심 | 10개 화면별 주인공·적·지역·아이템 키아트와 썸네일 세트 |
| 프레임 | 각진 패널과 공통 팔레트 적용 | 화면별 목재/황동 프레임 변주, 섹션 헤더 규칙 통일 |
| 정보 위계 | 핵심 수치와 로그 표시 | 제목→상태→행동→보상 순서가 모든 화면에서 일관 |
| 피드백 | 탭·버튼·로그 갱신 | 선택/획득/승리/잠금/실패의 상태 색·아이콘·짧은 모션 |
| 텍스트 | 기능 설명 중심 | 짧은 무협 문장, 상태 라벨, 숫자 포맷을 포함한 편집 품질 |
| 반응형 | 390×844 검수 완료 | 320~520px 구간 overflow 0, 데스크톱 중앙 모바일 프레임 |
| 접근성 | 하단 탭 Semantics | 주요 버튼·게이지·로그·모달까지 읽기 순서와 상태 제공 |

## 3. 실행 단계

### Phase A — 시각 토큰 2차 확정 (P0)

- 색상, 테두리 두께, 패널 내부 여백, 제목/본문/숫자 스타일을 토큰 파일로 추출
- `Panel`, `SectionHeader`, `GameButton`, `StatusMeter`, `ArtworkFrame` 공통 위젯화
- 10개 화면의 좌우 여백·섹션 간격·하단 탭 높이를 수치로 고정
- 완료 기준: 같은 토큰 변경으로 모든 화면의 프레임/버튼/헤더가 동시에 갱신되고, 기존 회귀 테스트 통과

### Phase B — 화면별 키아트와 아이템 아트 (P0)

- 시작: 타이틀 커버와 로고 장식
- 강호: 주인공/일반 적/지역 배경/전투 오버레이
- 지역·보스: 7개 지역 배경, 7개 보스 초상, 드랍 아이콘
- 무인·장비: 장비 8슬롯 실루엣과 등급별 프레임
- 무도·경맥: 비급 표지, 경맥 중심 문양/분기 아이콘
- 기연·강호록: 사건 배경, 기록지/도감 질감
- 완료 기준: 모든 주요 카드가 깨진 이미지나 단색 placeholder 없이 동일한 아트 규칙을 사용

### Phase C — 10개 화면 레이아웃 완성 (P0)

1. 시작 화면: 타이틀 영역, 저장 슬롯 상태, 새 강호/이어하기 우선순위
2. 강호 메인: 상태→지역→VS→로그→자동전투 순서 고정, 첫 viewport 핵심 정보 보장
3. 지역 선택: 7개 카드의 진행/잠금/권장 경지 비교
4. 지역 상세/보스: 지역 키아트, 적 목록, 주요 드랍, 기연, 보스 도전
5. 보스 전투: 보스 초상, 기혈, 전투 로그, 첫 처치 보상
6. 무인: 초상, 경지, 능력치 투자, 전투력, 8슬롯 장비
7. 장비 상세: 등급, 품질, 옵션, 현재 장비 대비, 장착/잠금/분해
8. 경맥: 중앙 시작점, 분기, 개방/가능/잠김 범례, 확대·이동·초기화
9. 무공 세팅: 5슬롯, 숙련도, 계열/등급, 현재 무도 효과
10. 기연: 사건 삽화, 설명, 2개 이상 선택지, 결과 피드백

완료 기준: 각 화면을 시안의 해당 패널과 나란히 놓았을 때 동일한 정보 구조와 밀도로 인식되며, 세로 스크롤 없이 첫 화면의 핵심 행동이 보인다.

### Phase D — 상태 피드백과 마이크로 인터랙션 (P1)

- 전투 로그 유형별 색상/아이콘/고정 우선순위
- 장비 획득·장착·분해, 무공 장착, 경맥 개방에 300ms 이내의 미세 피드백
- 보스 승리 보상 패널과 엔딩 전환의 단계적 연출
- 잠금·부족한 포인트·조건 미달에 명확한 사유 표시
- 완료 기준: 모든 주요 사용자 행동에 1초 이내 시각 또는 텍스트 피드백

### Phase E — 품질·접근성·배포 (P0)

- 320×700, 390×844, 520×900 세 viewport 스냅샷 검수
- 텍스트 대비, 최소 터치 영역 44px, Semantics 읽기 순서 확인
- 신규 아트 asset 누락 및 매핑 fallback 자동 테스트
- `flutter analyze`, `flutter test`, `flutter build web --release`를 PR 기준으로 고정
- Pages 배포 후 캐시/새 저장/이어하기/오프라인 보상 스모크 테스트

## 4. 우선순위와 작업 단위

한 작업은 하나의 화면 또는 하나의 공통 컴포넌트만 다룬다. 각 작업은 `feat:`, `fix:`, `test:`, `docs:` 중 하나의 커밋으로 남기고 공개 Pages에서 확인한다.

1. 공통 위젯·토큰 2차 추출
2. 강호 메인과 지역/보스 화면 아트 완성
3. 무인·장비 상세의 슬롯/비교 위계 완성
4. 무도·경맥의 노드/세팅 정보 위계 완성
5. 기연·강호록의 사건/기록 연출 완성
6. 전 화면 상태 피드백·접근성·반응형 회귀
7. `v0.2.0-alpha` 후보 검수 및 릴리스

## 5. 완료 정의

- 10개 화면 모두 시안과 같은 세로형 정보 밀도와 독립적인 무협 아트를 가진다.
- 플레이 루프와 저장 데이터가 UI 개편 전후 동일하게 동작한다.
- 320~520px에서 overflow와 치명적 레이아웃 깨짐이 없다.
- 주요 상태 변화가 색상·아이콘·텍스트 중 두 가지 이상으로 피드백된다.
- 자동 테스트·웹 빌드·Pages 검수를 통과하고 `v0.2.0-alpha`로 태그할 수 있다.
