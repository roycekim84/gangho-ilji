# 전체 게임 품질 감사 — 2026-09-07

## 범위

시작 화면부터 자동 전투, 지역 이동, 보스, 무인 성장, 장비, 무공·경맥, 기연, 오프라인 보상, 강호록, 엔딩까지의 코드 흐름과 웹 release 빌드를 점검했다. 기존 저장 구조와 게임 밸런스는 유지하는 것을 전제로 한다.

## 확인된 상태

- 자동 전투·7개 지역·7개 보스·장비·무공·경맥·기연·오프라인·엔딩 흐름이 단일 로컬 저장 슬롯으로 연결되어 있다.
- 21개 회귀 테스트가 통과하고, 웹 release 빌드가 생성된다.
- 모바일 화면은 중앙 520px 프레임으로 제한되며, 경맥 차트는 뷰포트 높이를 반영해 초기 축소된다.

## 우선순위 개선 목록

### P0 — 플레이 신뢰성

1. 강호 메인 진행도는 현재 `68%` 임시값과 보스 격파 여부만 사용한다. 지역별 처치·보스 상태를 반영하는 명시적인 진행도 계산으로 교체해야 한다.
2. 저장 데이터의 숫자·목록 필드가 손상되거나 타입이 달라도 부팅이 중단되지 않도록 모델 파싱을 방어적으로 보강해야 한다.
3. 오프라인 보상 수령 중 중복 클릭·재진입을 막고, 보상 계산 기준 시각을 수령 시점으로 갱신하는 회귀 테스트를 추가해야 한다.

### P1 — 성장 체감

1. 현재 무공 숙련도는 활성 무공 수와 처치 수로 계산되어 무공별 사용 숙련도 요구사항과 다르다. 무공별 숙련도 저장 필드와 발동 시 증가 처리가 필요하다.
2. 경맥 분기 효과는 일부 공격·방어·치명타에 반영되지만, 범례의 모든 분기가 전투 결과에 영향을 주는지 정리하고 미반영 분기는 설명을 수정해야 한다.
3. 장비 드랍·분해·장착 피드백을 장비 상세와 행낭 목록에서 동일한 문맥으로 제공해야 한다.

### P1 — 화면 완성도

1. 시작 화면은 새 강호 중심이며 이어하기·설정 진입이 별도 버튼으로 드러나지 않는다. 저장 슬롯 상태와 재개 액션을 명시해야 한다.
2. 강호 메인 지역 헤더는 320px 폭에서 지역명·진행도·두 액션 버튼이 밀집될 수 있으므로 작은 폭 레이아웃을 별도 검수해야 한다.
3. 무인·행낭·강호록 일부 화면은 공통 아이콘 fallback 비중이 높다. 전용 실루엣 또는 기존 자산 재사용으로 화면별 아트 밀도를 높여야 한다.

### P2 — 유지보수·접근성

1. `lib/main.dart` 단일 파일 구조로 인해 화면 변경 영향 범위가 넓다. 기능 변경이 안정화된 뒤 모델·게임 로직·공통 위젯을 단계적으로 분리한다.
2. `flutter analyze`의 기존 info/deprecation 104건을 단계적으로 줄이고, 특히 버튼 상태·게이지·오버레이의 Semantics 회귀 테스트를 확대한다.
3. 320×700, 390×844, 520×900에서 주요 화면 스냅샷을 자동 비교할 수 있는 시각 회귀 기반을 마련한다.

## 이번 점검에서 즉시 수정한 항목

- 기연 경험치 보상이 즉시 레벨업·능력점·경맥점에 반영되도록 공통 경험치 처리 경로를 추가했다.
- 보스 처치 후 일반 전투용 기연·장비 판정이 섞이지 않도록 보스 여부를 처치 시작 시점에 고정했다.

## 다음 권장 작업

강호 메인 진행도 계산을 먼저 명시화한 뒤, 무공별 숙련도 저장·발동 증가를 추가한다. 두 작업은 기존 저장 데이터에 기본값을 적용할 수 있어 호환성을 유지하면서 플레이 체감을 높일 수 있다.
